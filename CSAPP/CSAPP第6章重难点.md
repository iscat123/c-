## 先记住这张表（全章的直觉锚点）

| 层 | 典型容量 | 延迟数量级 | 备注 |
|---|---|---|---|
| 寄存器 | 数百 B | ~0.3 ns | |
| L1 cache | 32~64 KB | ~1 ns（约 4 周期） | SRAM |
| L2 cache | 256 KB~1 MB | ~4 ns | SRAM |
| L3 cache | 数 MB~数十 MB | ~10–20 ns | SRAM，多核共享 |
| 主存（DRAM） | 数 GB~数百 GB | ~60–100 ns | 比上一级慢约一个数量级 |
| SSD | 数百 GB~TB | ~50–100 μs | 比主存慢约 1000 倍 |

## 6.1 存储技术（本章的"字典区"，快扫）

### 6.1.1 随机访问存储器

1. **静态 RAM（SRAM）** ★★
   - 双稳态（触发器），有电即保持，不需刷新；快、贵、密度低、功耗大。
   - 用途定位：做缓存（L1/L2/L3）。

2. **动态 RAM（DRAM）** ★★
   - 每位 = 1 电容 + 1 晶体管；电容漏电须 ~ms 级刷新；对干扰敏感（光线都能翻转位）。
   - 用途定位：做主存。SRAM vs DRAM 的对比表值得记（速度/成本/刷新/用途）。

3. **传统的 DRAM** ★★
   - 超单元（supercell）二维阵列；行地址（RAS）→ 整行进**行缓冲区** → 列地址（CAS）→ 取出目标超单元。
   - **为什么重要**：行缓冲区是"整行预取"思想的硬件源头，也是理解后续访问延迟差异的基础。书上的阵列图抄进笔记。

4. **内存模块** ★
   - 多个 DRAM 芯片焊在模块上，内存控制器一次访问各芯片并行出 8 位，拼成 64 位（+ 纠错位）。

5. **增强的 DRAM** ★
   - 一句话：FPM/EDO → SDRAM（时钟同步）→ DDR（上下沿都传数据，DDR2/3/4 靠加大预取缓冲提高速率）→ VRAM（显卡双端口）。

6. **非易失性存储器** ★
   - PROM/EPROM/EEPROM/闪存（Flash）；断电不丢；固件存在 ROM 里；SSD 基于 Flash。

7. **访问主存** ★★
   - 一次读事务的完整流程：CPU 发地址 → 总线 → 内存控制器 → 行地址激活 → 列地址 → 数据回传总线。
   - **难点**：书上时序图，看懂一次即可，不必背步骤顺序。

### 6.1.2 磁盘存储 ★★（会算即可）

- 术语（盘片/表面/磁道/扇区/间隙/柱面）★：柱面 = 所有盘片同半径磁道的集合。
- **容量计算** ★★：容量 = 每扇区字节数 × 每磁道扇区数 × 每面磁道数 × 面数。
- **访问时间三段式** ★★★：`T_access = T_seek + T_rotation + T_transfer`
  - 平均寻道 ~3–9 ms；平均旋转延迟 = 半圈时间 = 0.5 × 60,000/RPM（7200 转 → ~4.2 ms）；
  - **必会计算**：给 RPM 和每道扇区数，算完整访问时间。这是课后计算题的固定题型。
- 工程含义：顺序 I/O 快、随机 I/O 慢的物理根源。

### 6.1.3 固态硬盘 ★★

- 结构：闪存翻译层（FTL）+ 闪存块（块由页组成）；读/写以**页**为单位，擦除以**块**为单位，页写前必须先擦整块。
- 推论（要会自己推出来）：写比读慢；随机写比顺序写慢（FTL 搬移整块）；有寿命 → 磨损均衡。
- 工程含义：日志顺序写、LSM 类结构的硬件根源。

## 6.2 局部性（★★★ 全章第一个"直接改变你代码"的节）

- **时间局部性 / 空间局部性定义** ★★★：被引用的信息，很可能**再次**被引用 / 其**邻近**信息很可能即将被引用。必须能一句话复述并各举一例。
- **步长（stride）与空间局部性** ★★★：步长越小越好，步长 1 最好；跳跃式引用（如按列遍历行主序数组）局部性差。
- **行序 vs 列序遍历二维数组** ★★★：`a[i][j]` 与 `a[j][i]` 只差循环顺序，性能可差数倍——这是全章最重要的一个"立刻能用"的知识点，笔记里必须配一个自己跑过的实验结论。
- **取指令的局部性** ★★：循环体小且连续 → 指令缓存命中高；大跳转 → 差。
- **局部性的判别方法** ★★★：对**内循环**逐变量问两个问题——步长是多少（空间局部性）？引用频率多高（时间局部性）？这个"方法"比记住任何单个例子重要。

## 6.3 存储器层次结构

- **层次结构总图** ★★★：寄存器→L1→L2→L3→主存→磁盘→网络；越往下越大、越慢、越便宜（每字节数量级差 10~1000 倍）。这张图是全书的"世界观图"。
- **"第 k 层是第 k+1 层的缓存"** ★★★：缓存不是新东西，是整个层次结构的组织原则；块是拷贝单位。
- **命中/不命中、命中率/不命中率、命中时间/不命中惩罚** ★★：定义要准。
- **不命中的三种分类** ★★★（难点，很多人只知其名）：
  1. **冷（强制性）不命中**——缓存空，首次访问，无法避免；
  2. **容量不命中**——工作集大于缓存；
  3. **冲突不命中**——多个块映射到同一组，缓存没满也被挤出去；极限情形叫**抖动（thrashing）**。
  - 判据：能对给定场景判断属于哪类。
- 替换/驱逐、牺牲块、LRU/LFU/随机 ★：概念知道即可，细节在 6.4.3 展开。

## 6.4 高速缓存存储器（★★★ 全章最难、考试和实践的核心，预算的一半给这里）

### 6.4.1 通用高速缓存结构 ★★★

- **地址划分是全章的心脏**：m 位物理地址 = **t 位标记（tag）｜ s 位组索引（set index）｜ b 位块偏移（block offset）**
- 四个参数：`S = 2^s`（组数）、`E`（每组行数）、`B = 2^b`（块大小字节）、`C = S × E × B`（总容量）。
- **必须达到闭眼能算的程度**：给任意三个量求第四个，再求 t/s/b 位数（t = m − s − b）。
- 笔记建议：记一道完整算例而不是记规则。例如：
  - 16 位地址，直接映射 S=4、B=8 → s=2、b=3、t=11；地址 0x0F6A = 0000 1111 0110 1010b → tag=0x7B（高 11 位）、组索引=01、块偏移=010。

### 6.4.2 直接映射高速缓存（E=1）★★★

- 三步：组选择（取地址中间 s 位）→ 行匹配（valid 位 + tag 相等）→ 字选择（低 b 位）。
- **冲突不命中的经典场景** ★★★：两个数组尺寸恰好使它们映射到同一组，交替访问 `x[i]`、`y[i]` → 每次 miss，抖动。
- **工程结论**：热点数据避免恰好相隔缓存大小（或 2 的幂）字节；书上"在尾部塞一个变量就解决冲突"的例子要记。

### 6.4.3 组相联高速缓存（1 < E < 行总数）★★★

- 组内 E 行并行比较，任何一行 tag 匹配即命中。
- 替换策略：随机 / LFU / LRU，各自权衡一句话。
- 为什么相联能减少冲突不命中——要能用自己的话讲清。

### 6.4.4 全相联高速缓存 ★★

- 整个缓存就一个组（无组索引位，地址 = tag + offset）。
- 为什么只适合小缓存（如 TLB）：并行匹配所有行的硬件成本随行数线性涨。

### 6.4.5 写的问题 ★★（概念易混，是对自己提问的好材料）

- 写命中两种：**直写**（write-through，立刻写下层，配**写缓冲**）vs **写回**（write-back，驱逐时才写，用**脏位**标记）。
- 写不命中两种：**写分配**（write-allocate，先把块读进缓存再写）vs **非写分配**（直接写下层）。
- 典型配对及原因：上层缓存用**写回+写分配**（减少下层流量），简单实现用**直写+非写分配**。
- 笔记建议：节末放一张 2×2 对比表——这是"横向串讲"最适合的一节。

### 6.4.6 真实缓存层次解剖（Core i7）★

- L1 i-cache / d-cache 分离（各 32KB，8 路），L2 256KB，L3 共享 8MB；指令与数据缓存分离的原因一句话。

### 6.4.7 缓存参数的性能影响 ★★★（难点：全是权衡，没有免费项）

| 参数增大 | 收益 | 代价 |
|---|---|---|
| 块大小 B↑ | 空间局部性利用好，miss率↓ | 行数变少→冲突miss↑、传输时间↑ |
| 缓存容量 C↑ | 容量miss↓ | 命中时间↑、功耗成本↑ |
| 相联度 E↑ | 冲突miss↓ | 命中时间↑（比较器复杂）、替换状态位↑ |

- 判据：给一条"参数↑"，能说出收益与代价两侧。

## 6.5 编写高速缓存友好的代码（★★★ 本章的工程产出，核心中的核心）

- **两条基本方法** ★★★：① 让最常见的情形跑得快（focus on inner loop）；② 内循环里尽量让每次 miss 摊到尽量多的计算上。
- **miss rate 估算** ★★★：例如块 64B、int 4B → 顺序扫描数组每 16 次访问 1 次 miss；块 32B → 每 8 次 1 次。要会按块大小现推。
- **累积变量放寄存器/局部变量**（时间局部性）、循环内引用次数分析——书上 sumrows 类例子要吃透。
- 判据：给出任意双重循环，能指出哪个变量访问模式好/差、坏在步长还是容量。

## 6.6 高速缓存对程序性能的影响（★★★ 用实验说话的一节）

### 6.6.1 存储山（Memory Mountain）★★★

- 读吞吐量关于（工作集大小 size，步长 stride）的曲面；
- **两条山脊**：沿 size 轴的台阶 = 时间局部性收益（工作集逐层跌出 L1/L2/L3）；沿 stride 轴的下降 = 空间局部性损失（stride 超过块大小后断崖）。
- 难点：能把三维曲面跟两类局部性一一对应；跑一遍 mountain 程序（或简化版）就能记住。
- 用途：一张图测出机器各层容量与带宽。

### 6.6.2 重新排列循环提高空间局部性 ★★★

- 矩阵乘法 6 种循环顺序，同一算法同一机器，**仅调换循环次序吞吐可差数倍**；
- 原因：`ijk`、`jik` 等版本内循环对 B 矩阵按**列**访问（步长 n）；`kij`、`ikj` 内循环全部步长 1 连续访问。
- **必做实验**：自己跑 3 种顺序对比时间，结论写进笔记——这是你笔记里最值得拥有的第一手数据。

### 6.6.3 分块（blocking/tiling）★★★ 全章工程价值最高的技术

- 思想：把 n³ 的整块工作切成 b×b 子块，使三个子块同时驻留缓存，每个元素被复用 b 次后才被驱逐——**用分块人为制造时间局部性**。
- 效果：miss 从"跟 n³ 同阶"降到"跟 n³/b 同阶"（直觉即可，精确推导可略）；
- **难点/判据**：b 怎么选？——使工作集（三个 b×b 子块 + 循环变量）小于目标缓存层（通常对 L1/L2 选 b=8~64 的 2 的幂，需实测）。
- 工程外延：分块思想通用于图像处理、数据库 join、数值计算——记一句"cache-blocking 是通用优化原语"。
